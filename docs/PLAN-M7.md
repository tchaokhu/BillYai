## สิ่งที่ทำ

### 1. `lib/flow/balance.ts` — จัดผลของ `computeDebts` ให้เป็นการ์ด (TDD, บริสุทธิ์)

รับ `PairDebt[]` กับตารางชื่อ คืนบล็อกตาม **D31**:

- **จัดกลุ่มตามเจ้าหนี้** — คนพิมพ์ `ยอด` คือคนที่ควักเงินไปก่อน เขาหาชื่อตัวเองใน
  หัวบล็อกแล้วอ่านจบในที่เดียว
- หัวบล็อกมี**ยอดรวมที่เจ้าหนี้คนนั้นได้คืน**
- เรียงบล็อกด้วยยอดรวมมากไปน้อย · ในบล็อกเรียงยอดมากไปน้อย · **เท่ากันตัดสินด้วยชื่อ**
  เพื่อให้ผลไม่ขึ้นกับลำดับที่บิลเข้ามา (เกณฑ์เดียวกับที่ `computeDebts` sort อยู่แล้ว)
- **ไม่ตัด** — Phase 1 ไม่มี LIFF ให้ไปดูส่วนที่ถูกตัด และ ledger ที่ซ่อนยอดโดยไม่มี
  ทางเปิดดูรับไม่ได้
- คู่ที่ยอดเป็นศูนย์ไม่โผล่ — `computeDebts` ตัดให้แล้ว

### 2. Flex การ์ด `ยอด`

- **ไม่มี Passive Nag ต่อท้าย** (D32) — ทั้งใบเป็นยอดค้างอยู่แล้ว
- **ยังไม่มีโทน Escalation** — อายุหนี้ (D33) เป็นของ Phase 2 พร้อม Passive Nag
- `altText` บอกยอดรวมทั้งวง — คนเห็นบรรทัดนี้ก่อนเห็นการ์ด

### 3. สองเคสที่ไม่ใช่ "มีหนี้"

| สถานะ | ตอบอะไร | ทำไม |
|---|---|---|
| วงยังไม่มีบิลสักใบ | **ไกด์** | ตัดสินไว้แล้วใน `DESIGN.md` §3 — เกณฑ์เดียวกับไกด์ใน 1:1 |
| มีบิลแล้วแต่เคลียร์กันหมด | **บอกว่าไม่มีใครติดใคร** | ต่างจากข้อบน: เขาใช้เป็นแล้ว ตอบไกด์ซ้ำคือไม่ตอบคำถาม |

### 4. ต่อสาย

- `lib/flow/dispatch.ts` เพิ่ม `balance` เข้า `IMPLEMENTED_COMMANDS` — **ที่เดียว**
  แล้วไกด์จะพูดถึง `ยอด` เอง (เทสต์ใน `messages.test.ts` บังคับไว้อยู่แล้ว)
- webhook เพิ่ม dependency อ่านยอด · **DB ล่ม → 500** ตามเกณฑ์เดิม
- `ยอด` ในแชท 1:1 อ่านวงส่วนตัวของคนนั้น เหมือนเส้นทางจดบิล

## ที่ต่างจากแผนตอนลงมือจริง

- **การ์ดที่ใหญ่เกิน bubble ลดรูปเป็นข้อความ** (D44) — เทสต์ที่เขียนเองจับได้ว่าวง 8 คน
  ที่ทุกคนเคยจ่าย (28 คู่) ได้ JSON 18 KB ทะลุเพดาน 10 KB · ตัวเลขใน D31 ที่ว่า "28 แถว
  ราว 3 KB" เป็นการเดาตอนตัดสิน ไม่ได้วัด — แก้ในตารางแล้ว
- **`loadGroupView` กับ `loadBalance` ย้ายไป `lib/repo/views.ts`** — เขียนไว้ใน route ก่อน
  ทั้งที่ไฟล์นั้นบอกตัวเองว่าเป็น "สายไฟอย่างเดียว" และของที่อยู่ในนั้นเทสต์ไม่ได้โดยไม่ยก
  Next.js ขึ้นมาทั้งตัว · ตอนนี้มี `views.db.test.ts` เดินเส้นทางเดียวกับผู้ใช้: จดบิล →
  กดยืนยัน → ถามยอด แล้วเทียบว่ายอดในการ์ดตรงกับที่ลง ledger จริง

## ยิงของจริงแล้ว — 1 ก.ย. 2026

ไล่ตารางข้างบนครบทั้งชุด **ผลตรงทุกข้อ** · การ์ดจัดกลุ่มตามเจ้าหนี้ ยอดตรงกับที่
การ์ดบิลโชว์ และสองคนจ่ายได้สองบล็อกแยกกันไม่ยุบข้ามคนตาม D5

### ที่วัดได้หลังไล่ครบทั้ง Phase 1

**invariant ของสคีมาผ่านทุกบิล** — query ที่เทียบ `Σ amount_satang` กับ
`round(total_satang * (1 + surcharge_pct/100))` ของทุกบิลที่ `status='active'`
คืน **0 แถว** ไม่มีใบไหนเงินหายหรือเงินงอก

**`totalUsage` = 0 ทั้งก่อนและหลัง** — ยิงครบทั้งชุดแล้วโควตายังไม่ขยับสักหน่วย
ซึ่งเป็นด่านเดียวที่จับได้ว่ามีเส้นทางไหนเผลอไปเรียก push แทน reply (C2)

### ที่โผล่มาระหว่างยิงจริง และกลายเป็น D45/D46

การ์ด `ยอด` ไม่ยุบข้ามคนตาม D5 จริง แต่**ยุบข้ามบิล**ของคู่เดียวกัน — เลขก้อนเดียว
ที่ไล่ไม่ได้ว่ามาจากใบไหน · ทางออกคือคำสั่ง `บิล` แยกอีกตัว ไม่ใช่แก้การ์ดนี้
เพราะสองอันตอบคนละคำถาม (`ยอด` = ตอนนี้ใครติดใคร · `บิล` = เกิดอะไรขึ้นบ้าง)
