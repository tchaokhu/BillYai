# Plan — M4: พูดกลับได้ (Phase 1 ก้อนที่ 1 จากสี่ ตาม D37)

ขอบเขตรอบนี้: **บอทตอบกลับเข้ากลุ่มและเข้าแชท 1:1 ได้จริง โดยไม่แตะ DB เลยสักบรรทัด**

ทำไมแยกก้อนนี้ออกมา: นี่คือรอบแรกที่ยิง LINE reply API ของจริง ระบบยังไม่เคยพูดออกไป
เลยสักครั้ง (`lib/line/` มีแค่ verify ลายเซ็นกับ narrow event ระดับหยาบ) ถ้า access token
ผิด scope ผิด หรือ reply token หมดอายุเร็วกว่าที่คิด จะได้รู้ตอนที่ยังไม่มี draft ให้เสียหาย

**ไม่มี migration ในรอบนี้** — `expense_draft` เป็นของ M5

## สิ่งที่ทำ

### 1. `lib/line/events.ts` — narrow JSON ของ LINE เป็น event ที่มีชนิด (TDD)

ฟังก์ชันบริสุทธิ์ รับ `unknown` คืน union ที่แคบแล้ว **ไม่เชื่อรูปร่างอะไรเลย** — body
ผ่านลายเซ็นแล้วก็จริง แต่ "มาจาก LINE" ไม่ได้แปลว่า "รูปร่างตรงกับที่เราจำ" (เหตุผลเดียว
กับที่ `lib/line/webhook.ts:52` เขียนไว้อยู่แล้ว)

ต้องได้ออกมา: ชนิด event (`message` ที่เป็น `text` · `postback` · อื่นๆ ทิ้ง) ·
`replyToken` · `source` ที่แยก `group` / `user` / `room` ออกจากกัน · `timestamp` (epoch ms)
· ข้อความ · `mention.mentionees[]`

- **`room` ไม่ใช่ `group`** — LINE มีทั้งสองอย่างและ `source.roomId` คนละฟิลด์กับ
  `source.groupId` · รอบนี้ `room` **ทิ้ง** ไม่ตอบอะไร เพราะ D21 ตัดสินว่า resolve วงจาก
  `source.type` เท่านั้น และยังไม่มีนิยามว่าวงในห้องแชทคืออะไร
- event type ที่ไม่รู้จักต้องข้ามเงียบๆ ไม่ throw — LINE เพิ่ม event ใหม่ได้ตลอดโดยไม่แจ้ง
- **`spentAt` มาจาก `timestamp` ของ event นี้** (D35) แต่ **ตัวแปลงอยู่ที่ `lib/time.ts`
  ไม่ใช่ในไฟล์นี้** (ต่างจากที่แผนเขียนไว้ตอนแรก ตัดสินตอนลงมือ): การแปลง epoch เป็น
  วันที่ไม่ใช่แนวคิดของ LINE และ §6 บังคับว่า core ต้องไม่รู้จัก LINE · `events.ts`
  ส่ง `timestamp` ดิบต่อไป ให้ชั้นที่สร้าง draft (M5) เป็นคนเรียกแปลง
- `lib/time.ts` ใช้ `Intl.DateTimeFormat` + `formatToParts` (ไม่พึ่งรูปแบบของ locale)
  · formatter สร้างครั้งเดียวระดับโมดูล · ชื่อโซนสะกดเหมือน `lib/repo/llm.ts:88`
  ฝั่ง SQL เป๊ะ เพื่อให้ grep คำเดียวเจอทุกที่ที่ระบบตัดสินขอบวัน · **ปักหมุด
  `calendar: 'gregory'` กับ `numberingSystem: 'latn'`** ไม่งั้น locale ไทยให้ปี
  พุทธศักราชเป็นเลขไทย แล้ว `2569-08-30` จะลง `date` ของ Postgres แบบเงียบๆ
  เทสต์ขอบวัน: `16:59:59Z` = วันนี้ · `17:00:00Z` = พรุ่งนี้ · ข้ามสิ้นเดือน · ข้ามปี

### 2. ตัด mention ออกจากข้อความ (TDD)

อยู่ในชั้น adapter ตามที่ `docs/DESIGN.md` §3 สั่งไว้ เพราะ `index`/`length` เป็นของ LINE
ล้วน — **`lib/parser/` ต้องไม่รู้จักคำว่า mentionee เลย**

- ใช้ `mentionees[].isSelf` ตัดสินว่าถูกเรียกไหม ไม่ใช่การเทียบชื่อในข้อความ
- `index`/`length` นับเป็น **UTF-16 code unit** — ต้องมีเทสต์ที่มี emoji และภาษาไทยอยู่
  ก่อนหน้า mention เพื่อจับกรณีตัดผิดตำแหน่ง
- mention หลายอันในข้อความเดียว ตัดทุกอันที่ `isSelf` แล้ว trim ก่อนส่งต่อ
- `@All` (`type: "all"`, `isSelf: false`) **ไม่เข้า Trigger** ตามที่ตัดสินไว้
- ตัดแล้วเหลือสตริงว่าง = `@บิลใหญ่` เดี่ยวๆ → ทักทาย + ไกด์

### 3. `lib/parser/` — ทางเข้าที่สอง + `BotCommand` ค่าใหม่ (TDD)

- เพิ่มฟังก์ชันรับข้อความที่ **ตัด mention ออกแล้ว** โดย **ไม่แตะ `parseMessage` เดิม**
  ซึ่ง `lib/contract.test.ts` ล็อกไว้ทั้งชุด · ข้อความที่มาทางนี้ไม่ต้องขึ้นต้นด้วย `+`
  เพราะ mention คือ Trigger ไปแล้ว
- `BotCommand` เพิ่มค่าสำหรับ "ทักทาย + ไกด์" · TypeScript จะบังคับให้ทุก `switch` ที่แตะ
  `BotCommand` อัปเดตตาม ซึ่งเป็นสิ่งที่ต้องการ ไม่ใช่ความรำคาญ
- `ยอด` ที่มีอะไรต่อท้าย (`ยอด #เชียงใหม่`) → คำสั่งที่ยังไม่เปิดใช้ ไม่ใช่ `unparsed` (D34)

### 4. `lib/flow/dispatch.ts` — ตัดสินว่าจะตอบอะไร (TDD)

ฟังก์ชันบริสุทธิ์: `(context, ParseResult) → ReplyPlan` โดย `ReplyPlan` เป็น**เจตนา**
ไม่ใช่ข้อความของ LINE (`'silent'` · `'guide'` · `'not-available'` พร้อมชื่อคำสั่ง)
— core ไม่รู้จัก LINE ตาม §6

ตารางที่ต้องมีเทสต์ครบทุกช่อง:

| ที่ไหน | ข้อความ | ตอบ |
|---|---|---|
| กลุ่ม | ไม่เข้า Trigger | **เงียบ** |
| กลุ่ม | `unparsed` | **เงียบ** (ตัดสิน 2026-08-29 — ยังไม่มี Haiku จนถึง Phase 4) |
| กลุ่ม | `@บิลใหญ่` เดี่ยวๆ | ทักทาย + ไกด์ |
| กลุ่ม | คำสั่งที่ยังไม่เปิด | ยังไม่เปิดใช้ |
| 1:1 | อะไรก็ตามที่ไม่ใช่คำสั่งที่เปิดแล้ว | **ไกด์** (กฎเงียบเป็นของกลุ่มเท่านั้น) |
| room | ทุกอย่าง | เงียบ |

**เรื่องที่ต้องรู้ตัวใน M4:** กฎจริงของ 1:1 คือ "ตอบไกด์เฉพาะตอนวงยังไม่มี Expense สักใบ"
ซึ่งต้องถาม DB · รอบนี้ **ไม่มีทางที่วงจะมี Expense ได้เลย** เพราะยังไม่มีเส้นทางเขียน
(ADR 0001: ไม่มีวง = ยังไม่มีบิลแน่นอน) — "ตอบไกด์เสมอ" จึงเป็นคำตอบที่ถูกในรอบนี้
ไม่ใช่ทางลัด · เงื่อนไขที่ถาม DB ไปลงที่ M6 ตอนที่วงเริ่มเกิดได้

### 5. รายชื่อคำสั่งที่ยังไม่เปิด — **ที่เดียวในระบบ**

ตัดสินไว้แล้วว่าต้องเก็บที่เดียว ไม่ใช่ `if` กระจายหลายที่ · รอบ M4 รายชื่อคือ
**`ยอด` `ทวง` `แก้` `เลิก` และการจดบิลด้วย `+`** — ทั้งหมดยังไม่มีของ

รายการนี้**หดลงทีละก้อน**: M6 เอาการจดบิลออก · M7 เอา `ยอด` ออก · Phase 2 เอา `ทวง` ออก
พอเอาชื่อออก ข้อความ "ยังไม่เปิดใช้" ก็หายไปเองโดยไม่ต้องไล่แก้ `if` ที่ไหน

**ไกด์ต้องไม่โฆษณาคำสั่งที่ยังไม่มี** — ข้อความไกด์ประกอบจากรายการเดียวกันนี้ ไม่ใช่
สตริงคงที่ที่เขียนแยก ไม่งั้นวันที่รายการเปลี่ยนจะมีที่หนึ่งที่ลืมแก้

### 6. `lib/line/client.ts` — ยิง reply API (TDD)

```
POST https://api.line.me/v2/bot/message/reply
Authorization: Bearer {channel access token}
Content-Type: application/json
{ replyToken, messages: [...] }        messages สูงสุด 5 ก้อนต่อครั้ง
```

- **`fetch` ฉีดเข้ามาเป็น dependency** — เทสต์ยูนิตห้ามยิงเน็ตจริง
- access token รับเป็นพารามิเตอร์ ไม่อ่าน `process.env` เอง (เหมือน `readChannelSecret`)
- timeout ชัดเจนด้วย `AbortSignal` — webhook ค้างรอ LINE คือทางเดียวที่จะพลาด reply token
- reply token ที่หมดอายุหรือใช้ไปแล้วได้ `400 {"message":"Invalid reply token"}`
  — แยก log ให้ต่างจาก error อื่น เพราะสองอย่างนี้แก้คนละทาง
- **ห้าม log ตัว token และห้าม log `replyToken`** — repo public และ log ไม่ควรสะสม
  ของที่ยิงซ้ำได้
- ไม่ retry เอง (D36 — 200 เสมอ) แค่ log ว่าพัง

### 7. `lib/line/messages.ts` — แปลง `ReplyPlan` เป็น message object (TDD)

รอบนี้เป็น **text message ล้วน ยังไม่มี Flex** — Flex ใบแรกคือ Draft card ของ M5

### 8. `lib/line/webhook.ts` + `app/api/line/webhook/route.ts` — ต่อสายจริง

- **ถอด DB probe ของ S4 ทิ้ง** (`findGroupByLineGroupId` กับ id ปลอม) — `lib/line/webhook.ts:19`
  เขียนไว้เองว่าการ probe ทิ้งแบบนี้ต้องหายไปตอน Phase 1 · รอบนี้ route ไม่แตะ DB เลย
- signature ไม่ผ่าน → `401` ไม่แตะอะไรต่อ (เหมือนเดิม)
- env หาย → `500` ไม่ใช่ `401` (เหมือนเดิม จงใจ ให้ LINE retry)
- **ผ่านลายเซ็นแล้ว → `200` เสมอ แม้ reply จะพัง** (D36)
- หนึ่ง request มีได้หลาย event — ตอบทีละ event ด้วย `replyToken` ของตัวเอง
  event หนึ่งพังต้องไม่ทำให้ที่เหลือไม่ถูกตอบ

### 9. env + ops

- `.env.local.example` เพิ่ม **`LINE_CHANNEL_ACCESS_TOKEN`** (ค่าว่าง) พร้อมคอมเมนต์ว่า
  อยู่แท็บ **Messaging API** ของ LINE Console **คนละตัวกับ channel secret** ที่อยู่แท็บ
  Basic settings

  ติดมา) เพราะเป็นค่าที่คนก๊อปวางจากหน้าเว็บเหมือนกันเป๊ะ
- ตั้งค่าบน Vercel scope Production · **Preview ยังไม่มี `LINE_CHANNEL_SECRET` โดยตั้งใจ**

- **เปิด greeting message ใน OA Manager แล้วเขียนข้อความจริง** — `docs/SETUP-LINE-OA.md`
  สั่งปิดไว้ตอน spike ต้องกลับไปเปิดและอัปเดตเอกสาร · ข้อความต้องสอดคล้องกับไกด์ในข้อ 5
