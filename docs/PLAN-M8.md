# Plan — M8: `บิล` (Phase 2 ก้อนแรก)

ขอบเขตรอบนี้: **พิมพ์ `@บิลใหญ่ บิล` แล้วได้รายการบิลที่กดดูรายละเอียดรายใบได้** (D45)
· และ **บังคับ mention ให้คำสั่งคีย์เวิร์ดทุกตัวเมื่ออยู่ในกลุ่ม** (D47)

รอบนี้เป็นฝั่งอ่านล้วน ไม่มีอะไรถูกเขียนลง DB เลยสักแถว

**ที่มา:** การ์ด `ยอด` ไม่ยุบข้ามคนตาม D5 จริง แต่ยุบข้ามบิลของคู่เดียวกัน — เดียร์ติดนัท
900 คือสามใบรวมร่างเป็นเลขเดียวที่ไล่ไม่ได้ว่ามาจากไหน · ทางออกคือคำสั่งใหม่ ไม่ใช่แก้
การ์ดเดิม เพราะสองอันตอบคนละคำถาม (`ยอด` = ตอนนี้ใครติดใคร · `บิล` = เกิดอะไรขึ้นบ้าง)

## สิ่งที่ทำ

### 1. D47 — คำสั่งคีย์เวิร์ดในกลุ่มต้อง mention

**เปลี่ยนพฤติกรรมของ `ยอด` ที่ขึ้น production ไปแล้ว** ทำก่อนข้ออื่นเพราะข้ออื่นสร้างอยู่บนมัน

| ที่ไหน | พิมพ์ | ผล |
|---|---|---|
| กลุ่ม | `@บิลใหญ่ ยอด` · `@บิลใหญ่ บิล` | คำสั่ง |
| กลุ่ม | `ยอด` · `บิล` เปล่าๆ | **เงียบ** |
| กลุ่ม | `+ ข้าว 300` | จดบิล — **ไม่แตะ** |
| 1:1 | `ยอด` · `บิล` เปล่าๆ | คำสั่ง — ไม่บังคับ mention |

เกณฑ์ 1:1 ยืมมาจากกฎเงียบตรงๆ (`lib/flow/dispatch.ts`): ที่นั่นไม่มีบทสนทนาของใครให้แทรก
เหตุผลของกฎหายไป กฎจึงไม่ตามไปด้วย · **และ LINE ไม่มี mention ในแชท 1:1 อยู่แล้ว**

**D34 หดลง** — เงื่อนไข "ส่วนต่อท้ายเป็น `#tag` ล้วนถึงจะนับเป็นคำสั่ง" มีไว้กัน `ยอด มาไหม`
ซึ่งตอนนี้ถูก mention กันให้หมดแล้ว · **ยังไม่ลบทิ้งในรอบนี้** — `@บิลใหญ่ ยอด #เชียงใหม่`
ยังต้องตอบว่ายังไม่เปิดใช้ ไม่ใช่ตอบยอดทั้งวงเงียบๆ

### 2. parser รู้จัก `บิล`

- `lib/types.ts` — `BotCommand` เพิ่ม `'bills'`
- `lib/parser/rules.ts` — คีย์เวิร์ด `บิล`
- `lib/line/messages.ts` — `COMMAND_HELP` เพิ่มบรรทัด `บิล — รายการบิลที่จดไว้`

### 3. `lib/repo/views.ts` — สองตัวอ่าน

```
loadBillList(group, limit)   →  N ใบล่าสุด + จำนวนทั้งหมด
loadBillDetail(expenseId)    →  บิลใบเดียวพร้อมรายคน
```

- `listExpenses` มีอยู่แล้ว รับ `limit` และกรอง `status='active'` ให้เรียบร้อย
- เรียงใหม่→เก่า: `spent_at desc, created_at desc, id desc` (มีอยู่แล้วในตัวมัน)
- **`listMembers` ต้องส่ง `{ includeLeft: true }`** ไม่งั้นชื่อคนที่ออกจากกลุ่มไปแล้วหายจาก
  บิลเก่า ซึ่งใน ledger คือยอดที่อ่านไม่รู้เรื่อง
- `loadBillDetail` **ต้องตรวจว่าบิลอยู่วงเดียวกับคนกด** — postback มาจากการ์ดที่ลอยอยู่ใน
  แชทได้ตลอดกาล ห้ามเชื่อว่า id ที่ส่งมาเป็นของวงนี้

### 4. `lib/flow/bills.ts` — จัดรายการเป็นการ์ด (TDD, บริสุทธิ์)

รับผลจาก repo คืนโครงการ์ด · ไม่มี I/O ไม่มีสูตรหนี้

- แถวหนึ่ง = ชื่อบิล + วันที่ + ยอดรวม · **ไม่มีรายชื่อคน** เพื่อให้แถวหนักคงที่ราว 250 ไบต์
  ไม่โตตามขนาดวง (นี่คือทั้งหมดของ D45)
- ท้ายการ์ดเขียนจำนวนที่เหลือเมื่อตัด — **ห้ามตัดเงียบ** (D31/D44)
- การ์ดรายละเอียด: ชื่อ + วันที่ + ยอดรวม + รายคน + ป้ายคนจ่าย — โครงเดียวกับการ์ด Draft
  **แต่ไม่มีปุ่ม** เพราะบิลลงไปแล้ว

### 5. postback

```
bill=<expenseId>
```

- **`expense.id` (uuid 36 ตัว) เท่านั้น ห้ามพาชื่อ** — ชื่อไทยผ่าน `encodeURIComponent`
  ยาวขึ้นเก้าเท่า ทะลุเพดาน 300 ตั้งแต่ชื่อยาวราว 27 ตัว (ADR 0002)
- รูปแบบเดียวกับ `confirm=<draftId>&as=<memberId>` ที่ใช้อยู่ — คนละ key จึงแยกกันได้

### 6. เคสที่ไม่ใช่ "มีบิล"

| สถานะ | ตอบอะไร | ทำไม |
|---|---|---|
| วงยังไม่มีบิลสักใบ | **ไกด์** | เกณฑ์เดียวกับ `ยอด` ในวงที่ยังไม่เคยจด |
| กดแถวของบิลที่ถูกยกเลิกแล้ว | **บอกว่าถูกยกเลิกแล้ว** | การ์ดเก่าลอยอยู่ในแชทและกดได้เสมอ (D30 ไม่มี hard delete) · เงียบอ่านออกว่าบอทพัง · โชว์ยอดเก่าคือตัวเลขผิดใน ledger |
| กดแถวของบิลที่อยู่คนละวง | **บอกว่าหาไม่เจอ** | ไม่บอกว่ามีอยู่จริงในวงอื่น |
| การ์ดใหญ่เกิน bubble | **ลดรูปเป็น text** | ทางเดิมของ D44 · เกิดยากกว่า `ยอด` มากเพราะแถวไม่โตตามขนาดวง |

**ยิงของจริง** — ในกลุ่ม LINE จริง:

| ทำอะไร | ต้องได้ |
|---|---|
| `ยอด` เปล่าๆ ในกลุ่ม | **เงียบสนิท** (เปลี่ยนจากเดิม — D47) |
| `@บิลใหญ่ ยอด` | การ์ดยอดเหมือนเดิมทุกประการ |
| `บิล` เปล่าๆ ในกลุ่ม | **เงียบสนิท** |
| `@บิลใหญ่ บิล` ในวงที่ยังไม่เคยจดบิล | ไกด์ |
| `@บิลใหญ่ บิล` หลังจดสามใบ | สามแถว ใหม่→เก่า มี `›` บอกว่ากดได้ |
| กดแถวหนึ่ง | การ์ดรายละเอียดใบนั้น ยอดรายคนตรงกับตอนจด · ป้ายคนจ่ายถูกคน |
| กดแถวเดิมซ้ำ | การ์ดเดิม ไม่มีอะไรเปลี่ยนใน DB |
| `ยอด` ใน 1:1 | ยังใช้ได้ ไม่ต้อง mention |
| `บิล` ใน 1:1 | รายการของวงส่วนตัว |
| `+ ข้าว 300 กอล์ฟ` | จดได้เหมือนเดิม **ไม่ต้อง mention** |

**ตรวจใน DB หลังทดสอบ:** ทุก query ในรอบนี้อ่านอย่างเดียว — `select count(*) from expense`
กับ `expense_share` ต้องเท่าเดิมเป๊ะก่อนและหลังกดดูรายละเอียดกี่ครั้งก็ตาม

**วัดโควตา** — `totalUsage` ต้องไม่ขยับ
