# LIFF ขยับขึ้นมาก่อนการทวง — งานแรกของมันคือ itemized

แผนเดิมวาง Phase 2 ไว้เป็นก้อนเดียวชื่อ "ทวงได้ เคลียร์ได้" (LIFF + PromptPay QR + Nudge +
Nudge Link + Settlement) โดยมี LIFF เป็นฐานของทุกอย่างในนั้น · **เราแยก LIFF ออกมาทำก่อน
และให้งานแรกของมันคือหน้าจอ itemized** ส่วนการทวงตามมาทีหลังบนฐานเดียวกัน

เหตุผลไม่ใช่ว่า itemized สำคัญกว่าการทวง แต่เป็นเรื่อง **อะไรกู้คืนได้และอะไรไม่ได้**:
บิลที่จดไม่ได้ในคืนนั้นหายถาวร ไม่มีใครกลับไปนั่งนึกว่าใครกินอะไรเมื่อสองสัปดาห์ก่อน ·
ส่วนหนี้ที่ยังทวงไม่ได้ยังนอนอยู่ใน ledger ครบถ้วน และวันนี้เจ้าของบิลก๊อปยอดจากการ์ด
`ยอด` ไปทวงเองในแชทได้อยู่แล้ว — ช้ากว่า แต่ไม่มีอะไรสูญหาย

การขยับนี้ไม่ทิ้งงานเลย: LIFF init, การ verify ID token ฝั่ง server (D15) และ route ของ
หน้าเว็บเป็นฐานร่วมที่ Nudge ต้องใช้อยู่แล้วทั้งชุด — ทำตอนนี้กับทำตอนหน้าได้ของเท่ากัน

## ทางที่ปฏิเสธ

**จดรายชิ้นด้วยไวยากรณ์ในแชทไปก่อน** — ตัดสินไปแล้วครั้งหนึ่งใน
`0003-itemized-grammar-in-chat.md` แล้วกลับคำวันเดียวกัน · ราคาที่แพงคือการพิมพ์ชื่อคนกิน
ต่อชิ้น ไม่ใช่ตัวไวยากรณ์ และมันตกกับคนพิมพ์ในจังหวะที่เขายืนอยู่หน้าเคาน์เตอร์ · การติ๊ก
ชื่อคือสิ่งที่หน้าเว็บทำได้ดีกว่าแชทอย่างขาดลอย และแชทก็ทำแบบติ๊กไม่ได้ด้วย เพราะ LINE
ไม่มีการแก้ข้อความที่ส่งไปแล้ว — แตะหนึ่งครั้งคือการ์ดใบใหม่เด้งในกลุ่ม

**ทำ Phase 2 เต็มก้อนตามแผนเดิมแล้วค่อยถึง itemized** — ได้ของครบกว่าตอนปล่อย แต่
ยืดเวลาที่ระบบยังจดใบเสร็จร้านอาหารไม่ได้ออกไปอีกทั้งก้อน ทั้งที่ backend ของ itemized
(`itemizedSubtotals`, `expense_item`, `expense_item_share`) ทำเสร็จและมีเทสต์คุมตั้งแต่
migration `0001`

**ยอมรับวิธียุบตามชุดคนกินเป็นคำตอบถาวร** — ได้หนี้เท่ากันทุกบาทจริง และยังเป็นคำตอบของ
Phase 1 ต่อไป · แต่สิ่งที่หายคือรายการรายชิ้น ซึ่งเป็นสิ่งเดียวที่ผู้ใช้ขอมาหลังยิง M8 จริง

## ผลที่ตามมา

- **ลำดับงานเปลี่ยน**: M9 = ฐาน LIFF + หน้าจอ itemized · การทวง QR Settlement Passive Nag
  เลื่อนไปเป็นก้อนถัดไป ไม่ได้ถูกตัดออก
- **ไวยากรณ์ในแชทไม่ต้องแตะเลย** — ไม่มี Trigger ตัวใหม่ ไม่มี `pendingItem` ไม่มีการเปลี่ยน
  ความหมายของการตัดบรรทัดใน `parseMessage` ซึ่งเป็นของที่ `lib/contract.test.ts` ล็อกไว้
- **`adjustment_satang` (ADR 0004) ยังจำเป็นและยังไม่ต้องรีบ** — ปัญหาการปัดเกิดกับทุก surface
  ที่มี Item ไม่ใช่เฉพาะแชท · migration ไปพร้อม M9 ไม่ใช่ตอนนี้ และต้องรันทั้งสอง
  Supabase project
- **D46 (`ดูทั้งหมด` เปิด LIFF) มีบ้านให้ลงแล้ว** — เดิมรอ Phase 2 ทั้งก้อนเพื่อปุ่มเดียว
- **`แก้` ก็เหมือนกัน** — §3 เขียนไว้ตั้งแต่ต้นว่า `แก้` คือการเปิด LIFF · มันยังอยู่ Phase 3
  ตามเดิม แต่เลิกเป็นคำสั่งที่ไม่มีที่ยืน
- **Deployment Protection ที่ปิดไว้บน preview กลายเป็นเรื่องใหญ่ขึ้น** — LIFF โหลดหน้าเว็บ
  จริงจากโดเมนนั้น การตัดสินว่าจะปิดถาวรหรือย้ายไป Protection Bypass for Automation
  (`SETUP-DEPLOY.md` §2.5(4)) ค้างมาตั้งแต่ตั้ง dev OA และตอนนี้ขวางทางอยู่
- การ์ดในแชทยังต้องโชว์รายการของบิล itemized ได้ (การ์ดรายละเอียดของ `บิล`) — งานฝั่ง
  Flex ไม่ได้หายไปทั้งหมด หายเฉพาะฝั่งรับข้อมูลเข้า
