ขอบเขตรอบนี้: **พิมพ์ `+ ข้าว 1200 กอล์ฟ` ในกลุ่มแล้วได้การ์ด Draft ที่ถูกต้องกลับมา**
พร้อมชื่อทุกคนและยอดรายคน · **ปุ่มยืนยันยังไม่ทำงาน** และ **ยังไม่มีอะไรลง ledger สักแถว**

ฝั่ง "อ่าน" ทั้งหมด สิ่งเดียวที่เขียนคือแถวใน `expense_draft` ซึ่งเป็นขยะที่ลบทิ้งได้เสมอ
ตาม ADR 0001 · ผลคือโค้ดที่แตะเงินจริงทั้งหมดกองอยู่ที่ M6 ก้อนเดียว ทบทวนได้โดยไม่มี

## สิ่งที่ทำ

### 1. `supabase/migrations/0002_expense_draft.sql` (D38 / ADR 0001)

```sql
create table expense_draft (
  id             uuid primary key default gen_random_uuid(),
  line_group_id  text,                    -- null = แชท 1:1 (วงส่วนตัว)
  line_user_id   text not null,           -- คนพิมพ์ (D26)
  payload        jsonb not null,
  spent_at       date not null,           -- D35 แช่ตั้งแต่ตอนสร้าง
  created_at     timestamptz not null default now()
);
```

- **ไม่มี `group_id` และไม่มี FK ไป `ledger_group`** — ตารางนี้ถือตัวตนฝั่ง LINE อย่างเดียว
  วงเกิดตอนกดยืนยันเสมอ ทั้งวงกลุ่มและวงส่วนตัว (D30) · แถวหมดอายุใน 24 ชม. อยู่แล้ว
- index: `(line_group_id, created_at)` สำหรับเก็บกวาดต่อกลุ่ม · `(created_at)` สำหรับกวาดทั่วไป
- อัปเดต `lib/db/schema.db.test.ts` ให้เฝ้าตารางที่ 11 นี้ด้วย

> **migration ต้องรันใส่ Supabase ทั้งสอง project ตามลำดับเดียวกัน** · `schema.db.test.ts`
> เฝ้าแค่ Postgres ใน Docker ที่ CI รัน มันไม่เคยเห็น Supabase ทั้งสองตัว ถ้าเพี้ยนกันจะ
> ไม่มีเทสต์จับได้ อาการคือ preview ผ่าน production พัง

### 2. `lib/db/rows.ts` — `ExpenseDraftRow` + mapper (TDD)

`payload` เป็น `jsonb` ซึ่งกลับมาเป็น `unknown` — **ต้อง validate ไม่ใช่ `as ExpenseDraft`**
payload ที่เขียนด้วยโค้ดเวอร์ชันก่อนหน้ายังนอนอยู่ในตารางได้ถึง 24 ชั่วโมงหลัง deploy

ตัว validate อยู่ที่เดียวและใช้ทั้งฝั่งอ่านและฝั่งเขียน · เจอ payload ที่อ่านไม่ออก =
ปฏิบัติเหมือน draft หมดอายุ (ตอบว่าการ์ดเก่าแล้วให้พิมพ์ใหม่) ไม่ใช่ throw ขึ้นไปถึง webhook

### 3. `lib/repo/drafts.ts` (TDD, `*.db.test.ts`)

- `createDraft(input, tx?)` — insert แล้วคืน id · **ลบของหมดอายุของกลุ่มเดียวกันใน
  statement เดียวกัน** ตาม ADR 0001 (เก็บกวาดตอนเขียน ไม่ใช่ด้วย cron เพราะ D7 บอกว่า
  v1 ไม่มี cron)
- `findDraft(id, tx?)` — คืน `null` เมื่อไม่เจอ **หรือเมื่อเกิน 24 ชม.** · อายุคิดจาก
  `created_at` ไม่ผูกกับขอบวัน `Asia/Bangkok` (ADR 0001 — ไม่งั้นบิลมื้อดึกเหลืออายุ 40 นาที)
- `deleteDraft(id, tx?)` — M6 ใช้ตอน commit · ใส่มาใน M5 พร้อมเทสต์ เพราะเป็นของคู่กัน
- รับ `PoolClient` ได้ทุกตัว (กติกาเดิมของ M2) — M6 ต้องเรียกใน transaction เดียวกับ
  `commitExpense`

### 4. Roster ตอน draft (D28)

**อ่านอย่างเดียว ไม่เขียน** — `listMembers` ของวงถ้ามีวง · ไม่มีวง (ยังไม่เคยยืนยันบิลเลย)
= Roster ว่าง = ทุกคนติดป้าย `(ใหม่)` ซึ่งถูกต้อง

- เทียบชื่อแบบ **exact ไม่ใช่ fuzzy** (D28 — เดาผิดแล้วบิลไปลงหัวคนผิดแบบเงียบ แย่กว่า
  พิมพ์ผิดแล้วเห็นป้าย)
- ชื่อที่ยังไม่มีในวงติดป้าย `(ใหม่)` บนการ์ด

### 5. คิดยอดรายคนสำหรับการ์ด

ใช้ `splitExpense` ของ M1 ตรงๆ — **ห้ามเขียนตรรกะกระจายเศษใหม่ที่ไหน** (`distribute`
คิดด้วย BigInt และมี invariant คุมอยู่แล้ว) · การ์ดโชว์ยอดที่คำนวณเสร็จแล้วเท่านั้น

`splitExpense` รับ `MemberId` แต่ตอน draft ยังไม่มี member จริงสำหรับคนใหม่ — ใช้ชื่อเป็น
คีย์ชั่วคราวในชั้นนี้ แล้ว M6 ค่อย map เป็น `MemberId` จริงตอนยืนยัน · **ยอดบนการ์ดกับยอด
ที่ลง ledger ต้องตรงกันเป๊ะ** เพราะคนกดยืนยันจากตัวเลขที่เห็น — เทสต์ต้องล็อกข้อนี้

### 6. Flex Draft card

- โชว์ **ชื่อทุกคนที่จะโดนหาร** และยอดรายคน (D16 — การโชว์ชื่อคือสิ่งที่ทำให้ Roster
  ที่โตเองไม่กลายเป็นบั๊กเงียบ)
- ป้าย `(ใหม่)` ข้างชื่อที่วงยังไม่รู้จัก
- **ไม่มี Passive Nag ต่อท้าย** (D32 / `CONTEXT.md`) — การ์ดนี้มีงานเดียวคือให้คนตรวจแล้วกด
- **ไม่โชว์วันที่** — คนเพิ่งพิมพ์ไปเมื่อกี้ วันที่บนการ์ดคือข้อมูลที่ไม่มีใครตรวจ
- ปุ่มยืนยัน: postback `data` เป็น **id ของ draft เท่านั้น** ซึ่งสั้นและยาวคงที่ ไม่มีวัน
  ชนเพดาน 300 ตัวอักษร (ADR 0001)
- `altText` ต้องอ่านรู้เรื่องตอนขึ้น notification — คนเห็นบรรทัดนี้ก่อนเห็นการ์ด

### 7. ต่อสายเข้า `lib/line/webhook.ts`

`decideReply` ได้เจตนาใหม่: จาก `not-available` เป็นการสร้าง draft · **ต้องแตะ DB แล้ว**
รอบนี้ จึงเป็นรอบแรกที่ `LineWebhookDeps` มี dependency ฝั่ง DB

- เอา `expense` ออกจากรายการ "ยังไม่เปิดใช้" ใน `lib/flow/dispatch.ts` (ที่เดียวตามที่
  ตัดสินไว้) แล้วไกด์จะเริ่มสอนไวยากรณ์จดบิลเอง — เทสต์ใน `messages.test.ts` บังคับอยู่แล้ว
- **DB ล่มตอนสร้าง draft → ตอบ 500 ไม่ใช่ 200** ตามเกณฑ์ "เขียนลงไปแล้วหรือยัง" (D36)
  รอบนี้เป็นรอบแรกที่เกณฑ์นั้นมีผลจริง

| `+ ข้าว 1201 กอล์ฟ ตูน` | เศษ 1 สตางค์ตกที่คนจ่าย ไม่ใช่หายไป |
| กดยืนยัน | ยังไม่มีอะไรเกิดขึ้น (M6) — ต้องไม่ error ไม่ค้าง |
| พิมพ์อีกใบในกลุ่มเดิม | การ์ดใหม่ ของเก่ายังอยู่ในแชทแต่ไม่มีผลอะไร |
